# Page-remapped merge candidate results

## Outcome

The edge-overlap layout cleared the registered 1.3× threshold at both sizes on both fresh seeds. At 1,048,576 records the gain was 1.326× and 1.334×. At 4,194,304 records it was 2.668× and 1.356×. These compare against the fastest of three references that each produce a fresh, contiguous, read-only output, through the first consumer scan. No non-control case cleared 1.5× on both seeds.

The 2.668× result mapped both outer slices, or 75% of the output. Each other edge-overlap run mapped only the first outer slice, or 37.5%, because the other run's source and output offsets differed modulo 4 KiB. The typical measured gain was lower than the 1.52–1.59× pilot estimate. When destruction of the output is added to the comparison, the four edge-overlap ratios remain 1.333×, 1.340×, 2.616× and 1.337×, in size and seed order.

## Where it loses

With an already-touched output, the hybrid reference was faster in all four edge-overlap combinations. Candidate speedup relative to that reference was 0.364–0.738×. This is a distinct resource contract and a useful bound on the benefit available when the caller already has a resident destination.

Bursty runs mapped 4.11–5.49% of the output and reached 0.838–0.854× versus fresh references. Interleaved runs mapped no pages and reached 0.822–0.862×. In interleaved cases the unmodified galloping bulk method alone beat the candidate by about 5–6% in paired time ratios. The best fresh reference was a scalar or hybrid merge in every measured interleaved pair. These controls expose the cost of the slice traversal and its mapping checks when the mechanism cannot skip payload copies. The adjacent control mapped all bytes and reached 6.878–7.633× against fresh output, or 1.823–1.966× against reused output. That control excludes overlapping ranges.

## Reproducibility and scope

All 400 measured outputs and 80 warm-ups matched the expected bytes. The run used one pinned logical CPU on an AMD Ryzen 7 5800X in Ubuntu 22.04.3 under WSL2. Peak process RSS was about 1,608 MiB, including input, output, verifier and eviction buffer. An aliased page can contribute to RSS through multiple virtual addresses. The measured mapped-byte counts show exactly how much output reused the input backing. See [machine and build metadata](metadata.txt).

The result covers synthetic two-run merges with already-backed immutable inputs, 128-byte records, a fresh destination and a sequential read of one word per cache line. Native Linux, real batch traces, the cost of converting ordinary allocations to a shareable backing, and novelty beyond RUMA-style assembly remain unverified. Teardown was measured after correctness verification and is reported separately.
