# Page-remapped merge pilot — 2026-11-12

- **Model** OpenAI GPT-6.1 Sol, Extra High, as identified by the owner. Exact token count and billed model cost are unavailable in the session. Local WSL compute has no incremental cloud charges.
- **State** Complete. Two of four non-control cases cleared the diagnostic threshold on both seeds. See [summary](summary.md), [calibration samples](calibration.csv), [merge samples](merge.csv) and [machine metadata](metadata.txt).

## Contract

Merge two ascending runs of 128-byte records on one thread. Each record has a unique `uint64_t` timestamp, its global rank as an ID, and deterministic payload. Inputs are already in RAM in page-aligned read-only views of a `memfd`. The output is a single contiguous read-only region in RAM. The input views remain intact and immutable while the output exists. This tests merge/compaction of already sorted batches. Preparing or converting the inputs is outside the measured operation for every method.

## A. How expensive is a remap?

- On the owner's Ryzen 7 5800X in Ubuntu WSL2, use one logical CPU, 4 KiB pages and 128 MiB of already resident data. Read and record the actual machine settings and compiler flags.
- Reverse the order of equal-sized source extents, with extents of 4 KiB, 64 KiB, 2 MiB, 16 MiB and 128 MiB. For each extent size, compare an anonymous output reservation plus `memcpy` with a reserved address range plus `mmap(MAP_SHARED | MAP_FIXED)` against the same `memfd`. Multiple pages within an extent share a single mapping call. The destination range is reserved before `MAP_FIXED` is used inside it.
- Time output allocation, assembly and making the output read-only, followed by a first sequential read of one word per cache line. Record assembly and scan times separately. A 64 MiB eviction buffer is touched before each trial. Verify the output byte-for-byte after timing. Run one warm-up and five measured repetitions, alternating order.

## B. How many pages could a merge reuse?

Use 1,048,576 and 4,194,304 records total and SplitMix64 seeds 271 and 1601. Generate monotonically increasing, unique timestamp slots with random intra-slot jitter. The generator splits these slots between two sorted runs using the following rules. The code receives just the two runs. The known merged byte sequence is used only for validation.

| Layout | How slots are assigned | Role |
|---|---|---|
| Adjacent | First half to A, second half to B | Positive control |
| Edge overlap | First `3N/8 + 3` slots to A, middle `N/4` slots assigned independently with equal probability, rest to B | Candidate workload |
| Bursty | Each 32,768-slot window starts with `28,672 + random(0..126)` slots exclusive to alternating runs. Remaining slots are assigned independently with equal probability. | Candidate workload |
| Interleaved | All slots assigned independently with equal probability | Negative control |

Walk the maximal consecutive slices in the merged order. For a slice from one run, a full page is eligible only if its source byte offset and its final output offset match modulo the page size. Count eligible bytes and maximal eligible extents, and group them by the largest calibration extent size that fits. Record the same coverage when alignment is ignored to expose the cost of misalignment. Verify that replaying the slice plan gives the exact merged output.

Measure a straight two-finger row merge and a run-aware merge that uses galloping search to locate consecutive slices and `memcpy` to copy them in bulk. Both produce a contiguous read-only result and include allocation, protection and the same first sequential scan as A. Verify all warm-ups and repetitions against the generated byte sequence. Use one warm-up and five measured repetitions, alternating method order and recording peak RSS. Benchmark processes run sequentially.

## Decision before building the candidate

For each size, layout and seed, start from the median paired minimum of the two measured reference totals. For each calibrated extent bucket, credit eligible bytes with the positive part of the median paired time saved by mapping instead of copying in A, scaled by bytes relative to the calibration volume. Subtract the sum from the reference time. The result is an optimistic estimate that assigns zero extra cost to planning and mixed mapping/copying. Treat a nonpositive prediction as an invalid estimate and inspect it before drawing conclusions.

Continue only if a non-control layout at one size estimates at least 1.3× on both seeds. A passing pilot permits a real candidate with fresh seeds and the same I/O contract. Report controls and regressions as well. These synthetic layouts test the mechanism, with practical relevance on real data still to be established.

## Reproduction

From the repository root on Linux or in WSL2, use GCC, Python 3 and 4 KiB base pages. The runner pins both processes to logical CPU 4 by default (`PAGE_MERGE_CPU` can override it), builds in a temporary directory and writes CSV and machine metadata to a new output directory.

```sh
bash runs/2026-11-12-page-remapped-merge/run.sh lab/page-merge-smoke --smoke
bash runs/2026-11-12-page-remapped-merge/run.sh lab/page-merge-pilot
python3 runs/2026-11-12-page-remapped-merge/analyze.py lab/page-merge-pilot
```

`source_aligned_bytes` counts full pages in each source slice while ignoring the destination offset. `eligible_*` columns count only pages that also align at the destination. The output is read-only, and assembly plus first scan are timed. Byte-for-byte verification and output teardown follow the timed interval.
